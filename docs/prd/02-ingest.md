# 流程二 PRD：资产入库与补充

> 覆盖：流程二-A（从 Agent 归集补充）、流程二-B（导入第三方 skill 库登记 + 只读关联）、流程二-C（第三方内容收集入库）。
> 依据：`docs/user-flows.md` 流程二。对应 data-flow §4.1 + EK-01/03。
> **时序约束**：本流程全部发生在打标签 / 维护 preset 之前——先让资产就位，再谈资产管理。

---

## 1. 目标
把散落的 skill 收进资产库、充实资产库，形成三类资产来源：Agent 归集、第三方库（只读）、第三方库自有副本。

## 2. 用户场景
- 归集补充：流程一-B 之后想再吸收某 Agent 的 skill。
- 引入第三方库：想把一个开源/外部技能库纳入可查、可复用。
- 自立副本：某个第三方 skill 想脱离上游独立维护。

## 3. 用户操作流程

### 3.1 流程二-A · 从 Agent 归集补充
步骤同流程一-B（B1–B5），复用「扫描归集 + 合并确认 + 可选接管」，此处不再展开。

### 3.2 流程二-B · 导入第三方 skill 库（登记 + 只读关联）
| 步骤 | 用户操作 | 工具响应 |
|---|---|---|
| B1 | 登记第三方库（目录 / git 地址），选布局 | 落库 `foreignSources[]`；flat/nested/auto 识别 |
| B2 | 选择关联方式：只读关联（默认） | linked=true：不拷贝本体，仅引用发现 |
| B3 | — | 自动探测标签体系：能检出的显示并默认开启，检不出的隐藏 |
| B4 | — | 实时发现库内 skills 及已开启体系的标签；归第三方来源命名空间 |
| B5 | 浏览/过滤库内 skill；在显示的体系上打/改标签 | hub 标签写仓库内/外文件 |
| B6 | （可选）并入个人资产库 | 走流程二-C 收集入库 |

### 3.3 流程二-C · 第三方内容导入个人资产库（收集入库）
| 步骤 | 用户操作 | 工具响应 |
|---|---|---|
| C1 | 在第三方库视图挑选要沉淀的 skill | 列出候选 |
| C2 | 触发「收集入库」 | 复制进个人资产库来源命名空间；同名去重 |
| C3 | 命中同名/近名 | 进入合并确认（版本/描述/来源，用户仲裁） |
| C4 | （可选）打标签、纳 preset | 副本归自有，写 frontmatter |

## 4. 核心功能点
1. **第三方库登记 + 布局识别**：flat / nested / auto 三模式适配不同库结构。
2. **只读关联（linked=true）**：只发现不拷贝，本体随上游更新。
3. **两套标签体系自动探测**：仓库自带（读 frontmatter）、hub 管理（写仓库内/外文件），可分别启用/禁用，检不出则隐藏。
4. **收集入库 + 合并确认**：第三方内容复制为自有副本，同名走仲裁。

## 5. 规则与边界
- **本流程先于打标签 / preset**：先让资产就位，再谈资产管理。
- 流程二-B 全程不改写第三方库本体（C3/C13）。
- 对第三方库**只做收集、不做接管**：第三方库保留原样，入库副本以链接/归档方式与来源关联。
- 第三方标签写仓库内/外文件，不落库内 SKILL.md（C14）。

## 6. 异常与降级
- 第三方库目录无权限 / 仓库不可达 → 保持只读态度，提示但允许浏览已缓存部分。
- 探测到标签形式与预期不符（无任何已知形式）→ 对应标签体系开关隐藏，不弹错。

## 7. 验收标准
- 登记第三方库后可实时浏览其 skill 与（启用的）标签，且库内本体零改动。
- 两套标签体系开关随探测结果正确显示/隐藏，切换禁用后不可打该体系。
- 收集入库的第三方 skill 成为自有副本，可独立打标；来源信息可溯源回第三方库。
