# 流程一 PRD：上手起步 · 初次进入建库

> 覆盖：引导式建库向导、流程一-A（导入已有个人资产库）、流程一-B（从 Agent 归集出资产库）。
> 依据：`docs/user-flows.md` 流程一。对应 data-flow §4.1。

---

## 1. 目标
在首次进入时，引导用户形成一份**可用的用户个人 skill 集（资产库）**，并完成基础配置（仓库路径、Agent 探测、活跃集合）。

## 2. 用户场景
- 场景 A：我已有现成的个人 skill 资产库，想直接纳入管理。
- 场景 B：我没有任何资产库，想让工具从我的 Agent 里归集出一份。
- 场景 C：我有个半空的库，想边用边补充（走 B 的现存库分支）。

## 3. 用户操作流程

### 3.1 引导：初次进入建库向导
| 步骤 | 用户操作 | 工具判断 / 响应 |
|---|---|---|
| 0.1 | 进入首启向导 | 提问「是否已有现成的个人 skill 资产库？」 |
| 0.2 | 有 → A；无 → B | 分支路由 |
| 0.3 | 配置仓库路径（新空目录 / 已有目录） | 落库 `repos[]` |
| 0.4 | 探测/确认 Agent，必要时覆盖自定义目录 | 内置清单 + 用户覆盖 |
| 0.5 | 设置「活跃 Agent 集合」 | 记 `activeAgents` |
| 0.6 | 完成向导 → 进入资产库首页 | 按分支落地 |

### 3.2 流程一-A · 导入已有个人资产库
| 步骤 | 用户操作 | 工具响应 |
|---|---|---|
| A1 | 指向已有 skill 资产库目录 / 仓库 | 实时扫描发现 skill 本体 |
| A2 | （无额外动作） | 纳入资产库视图；库内重名按 name 归一化 |
| A3 | 打标签补全 | 自有 → 写 SKILL.md frontmatter |

### 3.3 流程一-B · 用 Agent 的 skill 归集出资产库
| 步骤 | 用户操作 | 工具响应 |
|---|---|---|
| B1 | 指定目标目录（空目录 / 现存库） | 落库 repos[]；空库自动初始化 |
| B2 | 触发「扫描归集」 | 扫描 Agent 目录列候选 |
| B3 | 挑选要沉淀的 skill | 收集=复制入仓；同名触发合并确认 |
| B3a | 合并确认：对比候选 | 并列展示版本 / 描述 / 来源，用户仲裁保留 |
| B4 | （可选）接管 | 源 Agent 目录改软链 → 资产库 |
| B5 | 打标签补全 | 自有 → 写 frontmatter |

## 4. 核心功能点
1. **引导式建库向导**：按"有无现成资产"分流 A/B，统一起步体验。
2. **资产扫描（scanAll）**：实时发现目录内 skill，不落中间快照。
3. **收集**：复制 skill 内容进资产库，源位置保持不变。
4. **接管**：源 Agent 目录替换为软链指向资产库（独立于收集、可分步）。
5. **合并确认**：同名 / 近名 skill 并列展示版本号、描述、来源，用户仲裁。
6. **打标签补全**：基于"未打标签"过滤，为资产补语义。

## 5. 规则与边界
- **流程 A 不涉及收集/接管**：导入的就是用户自己的库本体，不复制不移动。
- 收集/接管仅发生于从 Agent 目录归集（B）或第三方汇入（流程二-C）。
- 归集只动「自有 / 收集 / 接管」目录；外部只读与 Agent 自带技能不碰（C13）。
- 「收集」与「接管」是两个**独立操作**，可分步执行（收集为先、接管按需）。

## 6. 异常与降级
- 目标目录不可写 / 权限不足 → 提示并停在收集前，不产生部分状态（C13）。
- 合并确认时无版本号 → 以描述 + 来源 + 更新时间作为并列依据（收敛见讨论点 2）。

## 7. 验收标准
- 首次进入可完成向导并进入资产库首页，流程可达。
- A/B 两条分支分别能落库可用的 repos[] 与 activeAgents。
- 归集产生的同名 skill 必然进入合并确认，用户可保留其一。
- 接管后源 Agent 目录为软链，指向资产库，验证无真实副本残留。
