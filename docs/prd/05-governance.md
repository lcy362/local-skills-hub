# 流程五 PRD：治理与体检 · 期望 vs 物理对账

> 依据：`docs/user-flows.md` 流程五。对应 data-flow 全图 + §5（体检中心、diagnose）。
> 原则：用户不主动改文件状态，而是通过体检中心"看清 + 就地修复"（C17）。

---

## 1. 目标
让期望集与物理目录之间的任何偏差**可见、可理解、可就地修复**，并预防"双事实漂移"。

## 2. 用户场景
- Agent 里出现失效软链、复制冲突、权限问题。
- 期望集与物理目录不一致，想一键看清并修复。
- 同一 skill 的标签在多个载体间漂移，想对齐。

## 3. 用户操作流程
| 触发 | 体检中心暴露 | 用户操作 |
|---|---|---|
| 失效软链 / 复制冲突 / 权限 / 双事实漂移 | diagnose 七类检查汇总 | 一键重试 / 就地处理 |
| 标签多载体漂移 | 一致性检查项 | 对齐载体 |

## 4. 核心功能点
1. **统一 diagnose**：汇总七类健康检查（Agent / 同步 / 重复 / 失效软链 / 仓库 / 项目 / 标签）。
2. **期望 vs 物理 diff**：单个 Agent / 项目可下钻查看差异明细。
3. **就地处理**：失效项一键重试 / 删除，权限问题提示。
4. **标签一致性检查**：同 skill 多载体标签漂移告警并比对齐（对应 G1 建议新增项）。

## 5. 规则与边界
- 体检只读暴露问题；一切修复动作仍走"决策→投影"规则，不绕过身份约束（C13/C17）。
- diagnose 覆盖范围对应 data-flow §5；标签一致性为待新增检查项（G1）。
- 任何自动逻辑不因体检而扩散到非活跃 Agent（C12）。

## 6. 异常与降级
- 某检查依赖的源头缺失（目录不存在）→ 归类并给出可执行的修复指引而非报错。
- 权限不足无法修复 → 明确提示所需权限，不静默跳过。

## 7. 验收标准
- 可一键触发 diagnose，七类检查结果清晰分类展示。
- 对 diagnosed 出的失效项，可就地一键重试 / 删除，修复后再诊无该项。
- 标签一致性检查能发现并对比多载体漂移，引导对齐载体。
