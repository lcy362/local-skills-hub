# Skills Hub 整体 PRD

> 依据 `docs/user-flows.md` 梳理的用户流程，为**本轮项目重构**产出的产品需求基线。产品功能层，不包含接口与实现细节。
> 配套文档：`docs/key-conventions.md`（关键约束 C1–C17）、`docs/data-flow.md`（数据流图）。

---

## 1. 文档定位

本文是重构的功能对标基准。核心设计理念一句话：

> **用户只做"决策"（定义期望），落地（投影到目录）由工具在触发点自动完成，物理状态永远可被推导。**

每个流程的落地都必须符合 `操作触发 → 同步生效` 的模型（无常驻 watcher）。

---

## 2. 产品概述

### 2.1 要解决的问题
- 用户的 skill 资产散落在多个 Agent 目录、外部库、项目目录里，无法统一沉淀、检索与复用。
- 资产标签、投放策略、项目关联往往散落多处，改动后物理目录却不一致，出现"双事实漂移"。
- 手动同步、手动维软链繁琐且易错。

### 2.2 愿景
把散落的 skill 收拢为一份 **用户个人 skill 集（资产库）**，并通过**第三方仓库**开放扩展；让"收资产、打标签、组 preset、投 Agent、挂项目"全程由"决策 + 自动投影"驱动。

---

## 3. 目标用户
- **技能创作者/重度用户**：有大量自建经验型 skill，需要沉淀、版本化、跨 Agent 复用。
- **Agent 使用者**：要给多个 Agent 精准投放不同 skill 组合。
- **项目协作用户**：需要把一组 skill 固定到具体项目，随项目提交。

---

## 4. 核心价值主张
1. **一份资产库**：所有个人 skill 本体与元信息维护在一起，可 git 管理。
2. **第三方仓库即字典**：开放库只读可查、可按需"自立副本"，不污染上游。
3. **标签即策略**：打标签 = 编码投放语义，自动驱动 Agent/项目关联。
4. **期望即现实**：任意配置变更，物理目录即时对账，无需手工同步。
5. **多 Agent / 项目共享**：一套本体，多处投影，互不复制、可提交。

---

## 5. 产品模型

```
config.json ──推导──▶ desired(期望集) ──投影──▶ 物理目录（软链/复制）
     ▲                                             │
     └────────── 体检 / 诊断 diffSync 对账 ◀────────┘
```

- **决策（config）**：repos / agents / presets / projects / activeAgents / skillMeta。
- **期望集（desired）**：由决策运行时推导，不落盘。
- **投影（projection）**：期望 → 物理目录的 diff 对账，幂等。
- **同步作用域**：默认只作用于**活跃 Agent**（activeAgents），非活跃懒同步。

---

## 6. 核心概念

| 概念 | 含义 |
|---|---|
| 用户个人 skill 集（资产库） | 用户经验沉淀的集中存放处，本体可 git 管理 |
| 第三方仓库 | 开放内容库，随上游更新；可登记、只读发现，不污染本体 |
| 收集 / 接管 | 收集=复制入资产库；接管=源位置改软链指向资产库（两步独立） |
| 合并确认 | 同名/近名 skill 交汇时，并列展示版本/描述/来源，由用户仲裁保留 |
| 期望集（desired） | Agent/项目"应装 skill 集合"，运行时计算，不落盘 |
| 标签载体 | 自有→SKILL.md frontmatter；第三方→仓库内/外文件（两套体系可开关） |
| 活跃 Agent（activeAgents） | 实时同步作用域集合 |

## 8. 全局设计原则（关键约束落点）

1. **期望由配置推导**：不保存"应该装什么"的计算结果（C6），任何时刻可重算。
2. **物理状态可推导**：物理目录是期望集的投影，无独立事实源（C1/C2）。
3. **管理信息与本体分离**：第三方仓库的标签等管理信息不写入上游本体（C3）。
4. **触发式同步**：无 watcher，同步在触发点即时完成（C10）。
5. **活跃即实时、非活跃即懒**（C12）：自动同步只作用于 activeAgents。
6. **幂等对账**：重复执行 diff 为空即不动（C7）。
7. **权限尊重**：不擅改外部/只读内容，对不符合权限的源保持只读（C13）。
8. **体检优先**：诊断暴露差异，用户就地修复，而非绕过规则（C16/C17）。

---

## 9. 范围与非目标

### 在范围
- 资产库管理、第三方仓库登记与读取、合并确认、标签管理、preset、Agent 投放、项目协作、体检中心。

### 非目标（本轮）
- 第三方 skill 本体内容的编辑与改版（只读尊重）。
- 定时 watcher 自动同步（坚持触发式）。
- 检测标签环境（如前端）的自动发现与注入（超出 skill 文件管理范畴）。

## 10. 里程碑（落地顺序）

| 里程碑 | 交付 | 覆盖流程 |
|---|---|---|
| M0 | 框架与模型落地：config/desired/投影/幂等对账骨架 | 全流程底座 |
| M1 | 首启建库向导 + 资产扫描与入库 + 合并确认 | 流程一、二 |
| M2 | 标签管理 + preset + Agent 管理 + 分发 | 流程三 |
| M3 | 项目协作 + 回写仓库 | 流程四 |
| M4 | 体检中心完善 | 流程五 |

---

## 11. 整体验收标准
- 首次进入可经引导完成资产库构建（流程一），流程可达。
- 任意决策变更（标签 / preset / explicit / 活跃集合）后，物理目录与期望集一致（可用 `diagnose` 验证）。
- 变更只在活跃 Agent 上即时生效，非活跃不被静默改动。
- 第三方仓库本体不被写入任何管理信息。
- 重复执行同一对账，结果幂等、无副作用。
