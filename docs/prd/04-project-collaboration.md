# 流程四 PRD：项目协作 · 一套本体、多 Agent 共享

> 依据：`docs/user-flows.md` 流程四。对应 data-flow §4.3（项目级链路）。
> 关键模型：`.agents/skills` 复制本体（可提交 git），各 Agent 项目级目录软链到 `.agents`；投放对象以目录结构为事实。

---

## 1. 目标
把一组 skill 固定到具体项目，随项目提交 git；让同一套本体被多个 Agent 的项目目录共享，避免多副本。

## 2. 用户场景
- 一个项目需要固定的后端 / 前端 / 部署技能集，希望随项目走、可提交。
- 不想在项目里复制多份同一 skill，希望 Agent 间共享一套本体。

## 3. 用户操作流程
| 步骤 | 用户操作 | 工具响应 |
|---|---|---|
| J1 | 登记/创建项目：路径、命名 | 记 projects[]：path/tags[]/explicitOn[]/explicitOff[] |
| J2 | 编辑项目 tags；可选对某 skill 显式开/关 | 标签命中进基准；explicit 为覆盖 |
| J3 | — | 期望 = 标签命中 ∪ explicitOn − explicitOff（运行时计算，不落盘） |
| J4 | 点「同步」 | syncProject：.agents/skills/ 复制本体 + 各 Agent 项目目录软链 → .agents |
| J5 | 决定投放的 Agent | 以目录结构为事实：软链存在与否即投放事实，不写 config |
| J6 | 改 tags / explicit 后 | 沿用已投放 Agent 集合重投 |
| J7 | 点「push 回仓库」 | .agents → 仓库 双向同步（PJ-05，未实现） |
| J8 | 关闭投放 / 删登记 | 解除软链、清登记；.agents 本体保留与否按需 |

## 4. 核心功能点
1. **项目登记与标签**：项目可有自己的 tags 与 explicit 覆盖。
2. **项目期望集**：由 tags/explicit 运行时推导，不落盘。
3. **同步到项目（syncProject）**：`.agents/skills` 复制本体 + 各 Agent 项目级目录软链。
4. **投放以目录结构为事实**：不写 config，避免双事实漂移。
5. **变更重投**：标签/覆盖改动后按已投放 Agent 重投。
6. **回写仓库**：把 `.agents` 修改推回真实仓库（标注未实现）。

## 5. 规则与边界
- **标签 = 投放策略而非快照**：改动沿用已投放 Agent 集合重投（§4.3，C6/C7）。
- `.agents/skills` 是项目唯一可提交 git 的本体副本（PJ-02）；Agent 项目级目录均软链到它（PJ-03）。
- **投放范围以目录结构为唯一事实**，不落入 config（避免双事实漂移，C13）。
- 回写仓库（J7）当前未实现，作为能力缺口明确标注（G3）。

## 6. 异常与降级
- 项目目录无权限 / 被占用 → 同步失败可重试，体检中心就地处理（并入流程五）。
- 待回写项检测到本体与仓库不一致 → 提示确认回写方向，避免覆盖。

## 7. 验收标准
- 同步后 `.agents/skills` 存在可提交 git 的本体副本，各 Agent 项目级目录为软链。
- 投放对象与实际目录软链一致，`diagnose` 无漂移告警。
- 改标签 / explicit 后，已投放 Agent 的物理投放自动更新。
- 未实现能力（回写仓库）在 UI 明确标注为不可用，不误导。
